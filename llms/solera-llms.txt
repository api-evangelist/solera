# Solera

> Solera is a Westlake, Texas headquartered vehicle lifecycle management software, data and services company operating in more than 100 countries. It is a claims-technology intermediary — it does not underwrite risk. Its insurance-facing business is automobile physical damage claims (first notice of loss intake, photo and AI damage assessment, repair cost estimating, total loss valuation, parts sourcing and claims workflow) delivered through the Audatex and Qapter brands, alongside Vehicle Repair (Identifix, Autodata, Hollander), Dealer Solutions (DealerSocket, cap hpi) and Fleet Solutions (Omnitracs, SmartDrive, eDriving).

Generated by API Evangelist on 2026-07-25. Solera publishes no llms.txt of its own (https://www.solera.com/llms.txt returns 404).

## How to integrate (read this first)

- There is NO self-serve developer portal, no signup, and no public API key. developer/developers/docs/api/apis subdomains on solera.com do not resolve; /developers, /developer, /api, /partners and /integrations return 404.
- The Solera Integrations portal at https://na.api.solera.com/ returns 200 but redirects to /Login and presents an Audatex User ID / Password form. It is a partner login wall.
- Onboarding is a provisioned B2B integration run by a Solera/Audatex account representative: meet prerequisites, review specs, build client-side services, establish a secure connection, test connectivity, complete UAT, go live. Production is scheduled no earlier than 5 business days after UAT signoff.
- What IS anonymously readable: the Swagger UI reference pages and machine-readable specifications on api-demo.audatex.com and api-prod.audatex.com, the OpenID Connect discovery documents on the Audatex IdentityServer, and the PDF/DOCX integration guides under https://na.api.solera.com/files/.
- Standards alignment is CIECA, not ACORD. Audatex is a Corporate Technology member of the Collision Industry Electronic Commerce Association and licensed to use CIECA standards; CIECA BMS 5.7 is the data mapping baseline, though Audatex "does not support all fields available in the CIECA BMS".

## Authentication

- OAuth 2.0 against the Audatex IdentityServer. HTTP Basic authentication is offered as an alternative.
- Production token endpoint: https://dispatch-login.audatex.com/connect/token
- Demo / UAT token endpoint: https://dispatch-login-demo.audatex.com/connect/token
- Discovery (anonymous, 200): https://dispatch-login.audatex.com/.well-known/openid-configuration
- Grants supported: authorization_code, client_credentials, refresh_token, implicit, password, device_code, delegation, apitoken. PKCE S256 supported.
- Resource scopes include b2b.fnol.api, b2b.fnol.documents, b2b.fnol.transformer, b2b.admin.api, gofnol.api, estimatics.api, hqclaims.api, novo.claims.manager, novo.estimating, mobile.inspection.api, marketdata.web.api, vinhistory.api, vindecode.api, PartsTrader.api, eagle.api.
- Multiple scopes may be requested on one token, space separated. Published sample token TTL is 43200 seconds.

## APIs

- [Solera Dashboard Assignment API](https://api-demo.audatex.com/TestAssignmentapi/docs/index.html): Assignment dispatch and FNOL intake. Create an assignment, fetch a sample assignment message, post acknowledgements, generate an estimate return response.
- [ClaimImages API](https://api-demo.audatex.com/TestClaimImageapi/docs/index.html): Retrieve a claim image by identifier and a decoded file.
- [EAPI GIC Integration API](https://api-demo.audatex.com/TestGICapi/docs/index.html): Post GIC integration payloads against a work assignment, acknowledge M31 events, report the deployed version.
- [Audatex GetDocuments API](https://api-prod.audatex.com/GetDocuments/docs/index.html): Retrieve claim documents and valuations by assignment id + locator, or by id.
- [Audatex Assignment Get Document API (GetImage)](https://api-prod.audatex.com/GetImage/docs/index.html): Retrieve a claim image document by locator.
- [EAPI Get Document API](https://api-demo.audatex.com/TestGetDocumentapi/docs/index.html): Document and valuation retrieval by assignment id, locator, type and process id.

## Events and callbacks

Audatex pushes claim lifecycle events to a CLIENT-hosted HTTPS endpoint registered per assignment in the responseRoute block. Audatex authenticates against the client's own authorization server, POSTs a HATEOAS message, and the client then authenticates back to Audatex and GETs each referenced document. Delivery is at-least-once: 3 retries with a 15 second timeout for estimate/claim-image callbacks, 3 retries every 10 seconds for the GIC M31 event, then a reject queue. There is no signature header.
